# Ostinascope — prototype

> 見えないリズムを、見えている形の中から掘り出す。

スマホのカメラ映像から**繰り返しパターン**（縞・格子・点の並び・同心円／放射）を検出し、種類に応じたループを鳴らす Web アプリのプロトタイプ。
スマホを動かすことがそのままミックスになる。企画書：`サウンドビジュアル_企画書.md`（Obsidian）。

ビルド不要の静的サイト（ES Modules）。依存パッケージなし。

---

## 動かす

| 目的 | コマンド | 開く URL |
| --- | --- | --- |
| PC で試す（デモポスター） | `python3 scripts/serve.py` | http://localhost:8000/?mode=demo |
| PC のカメラで試す | 同上 | http://localhost:8000/ |
| スマホ実機で試す（同じ Wi-Fi） | `python3 scripts/serve.py --https` | 表示される `https://<LAN-IP>:8443/` |
| テスト | `npm test`（= `node --test test/*.test.mjs`） | — |

- カメラは **HTTPS か localhost** でしか使えない。`--https` は自己署名証明書を `.cert/` に作る（git 管理外）。iPhone では警告画面で「詳細を表示 → このWebサイトを閲覧」。
- 安定した実機テスト・展示は **GitHub Pages** に置くのが確実（リポジトリ直下をそのまま公開すればよい）。
- iPhone は「タップして開始」で音が有効になる。消音スイッチ ON でも鳴るよう `navigator.audioSession` を設定済み（iOS 16.4+）。
- URL に `?debug` を付けると解析セルと統計を表示し、コンソールから `window.ostinascope` で内部状態を触れる。

### デモモード
カメラなしで、生成したポスター（パターン標本）を「カメラで覗いている」状態をシミュレートする。
ドラッグで移動、ホイール／ピンチで拡大縮小、6 秒放置で自動巡回。設定パネルから任意の画像を読み込んだり、デモポスターを印刷用 PNG（3600×5092）で保存して実機テストに使える。

## 仕組み

```
カメラ / デモ画像
   │ 2倍ずつ縮小（エイリアシング＝偽モアレ防止）
   ▼
解析画像 192px（短辺）── 10 Hz ── Web Worker ──┐
                                                ▼
 detector.js  半分ずつ重ねたセル(32×32)ごとに 2D FFT ×4 階層（1×・2×・2.8×・4× 縮小）
   │  縞 / 格子 / 点 を判定 → 隣接セルを統合 → 同心円・放射は向きの収束で判定
   ▼
 tracker.js   フレーム間で ID を追跡（数フレームで確定、見失ったらフェード）
   ▼
 mapping.js   パターンの性質 → ループ（拍の分割・音高・音色・音量・定位）
   ▼
 audio.js     共有テンポ上で先読みスケジューリング（Web Audio, 全音源シンセ）
 render.js    検出領域・寸法線・注記・出口の痕跡・スコアを重ねて描画
```

### 検出（`src/detector.js`）
1. 画面を 32×32 px のセルに分ける。セルは**半分ずつ重ねて**並べる（模様がセルの格子とずれていても、どこかのセルにきちんと収まる）。
2. 解像度を変えた **4 階層**（192px 短辺の 1×・2×・2.8×・4× 縮小）で同じことをする。細かい模様は 1×、大きな模様は粗い階層が担当し、画面幅の約 1.4%〜29% の間隔を拾う。近づく／離れると担当が切り替わる。
3. セルごとに平均を引いて Hann 窓 → 2D FFT（実数入力用に半分の計算量）→ パワースペクトルの極大を探す。
4. 「繰り返し」と認める関門（どれかに落ちたら鳴らさない）：
   - **突出度**：同じ半径の帯の中央値の 20 倍以上（ランダムな質感は数倍止まり）
   - **鋭さ**：ピーク周り 5×5 のエネルギーのうち 85% 以上が中心 3×3 にある（髪・葉・砂利などの質感は山が広い）。突出度が 100 倍を超える強いピークは 70% で可（波打つ金網、斜めから見た紙）
   - **3 回以上の繰り返し**：周期方向の 1 次元プロファイルが 2 周期先と相関 0.35 以上（遠近で間隔がずれるので ±15% の幅で探す。平行線 2 本・紙の縁＋枠線などを除外）
   - **集中度**：模様の周波数より上の帯域で、1 方向（＋倍音）がエネルギーの 20% 以上（格子は 2 方向で 30%）。陰影や大きな輪郭の低周波は数えない
5. 2 方向目のピークがあれば格子。交差項（k1±k2）が強ければ **DOTS**、弱ければ **GRID**。
6. 同じ種類・周期・向きの隣接セルを統合（階層ごとに最低 3/2/2/1 セル。それより小さい領域は突出度 1000 倍以上などよほど明瞭な場合だけ）。小さな隙間は橋渡し、関門をわずかに外したセルは領域の縁として取り込む。格子の縁で片方向しか見えないセルは格子に吸収。
7. 縞セルの集まりで向きが扇状に広がっていれば、各セルの法線（同心円）／縞の向き（放射）が 1 点に収束するかを最小二乗で確認 → **CONCENTRIC / RADIAL**。
8. 色は領域内の「より彩度の高い側」（色インク or 色紙）から取る。

解析は Web Worker で行う（スマホで 1 フレーム 10〜40 ms 程度でも描画と音のスケジューリングが止まらない）。間に合わないフレームは捨てる。

### 追跡（`src/tracker.js`）
- 3 フレーム（≥250 ms）連続で見えたら確定 → ループ開始。
- 350 ms 見失ったらフェードアウト開始（縞 1 小節、その他 2 小節）。途中で戻れば復帰。
- 画面の縁から出て行った場合は、出た方向の縁に痕跡（矢印と注記）を残す。

### 音（`src/mapping.js`, `src/audio.js`）
| パターン | ループ |
| --- | --- |
| STRIPE | 間隔で拍の分割：細 → 1/16・1/8（ハイハット）、粗 → 1/4・1/2（キック） |
| GRID | 2 つの間隔の比を小さな整数比に丸めてポリリズム（例 3:4 → 3 対 4） |
| DOTS | ユークリッド・リズム E(k,16)（密なほど k が大きい）の短い打音、音程は輪郭パターン |
| CONCENTRIC / RADIAL | ドローン（根音＋5度＋オクターブ）。テンポ同期のフィルタのうねり |

| 見た目 | 音 |
| --- | --- |
| 色 | 音高（D マイナー・ペンタトニック。黄＝高い、青＝低い、無彩色＝根音） |
| シャープネス（倍音の強さ） | アタック・硬さ |
| コントラスト・面積 | 音量 |
| 縞の向き | パン（45° と 135° が左右に分かれる） |

- テンポは全体で 1 つ（既定 108 BPM）。新しいループは**次の拍の頭**から入り、構造の変化（分割・比など）は 3 回連続で要求されたら**次の小節線**で切り替わる。
- まったく同じループになるパターン（同じ図形が並んでいる等）は 1 声にまとめて鳴らす（注記に `＝05` のように表示）。
- 同時に鳴るループの上限（既定 6）を超えた分は `MUTED` 表示。

## 調整できるところ

| 何を | どこ |
| --- | --- |
| BPM・感度・ループ上限・音量 | アプリ右上の設定パネル |
| 判定の閾値（突出度・鋭さ・繰り返し・集中度・DOTS/GRID の境目・階層ごとの最小セル数…） | `DETECTOR_DEFAULTS`（`src/detector.js`） |
| 確定までのフレーム数・見失いの猶予・追跡の許容量 | `TRACKER_DEFAULTS`（`src/tracker.js`） |
| 間隔 → 拍の分割の境目、色 → 音高の表、音色 | `src/mapping.js` |
| フェードの長さ | `fadeBarsFor`（`src/mapping.js`） |
| デモポスターの構図 | `src/poster.js` |

## 現状と次にやること

確認済み（PC の Chrome）：デモポスターで全種類が検出され、Worker 上で 1 フレームあたり約 15 ms・10 Hz で解析できる。印刷したポスターを手持ちで撮った映像（傾き・ぼけ・手ぶれ・照明むら・ノイズを付けたもの）を Chrome の疑似カメラに流すと、各図の前で正しい種類のループが鳴っている割合は 100%（32/32 サンプル）。

カメラで反応が鈍かった点の見直し（2026-11）：実写写真 82 枚（Wikimedia Commons：ブラインド・横断歩道・階段・鍵盤・レンガ・金網・キーボード・水玉・建物の窓など＋人物・自然・食べ物・机）から切り出した 1,640 ビューと、実写背景に模様を合成した 300 枚・手持ちの連続フレーム 60 本で旧版と比べた。
- 4 周期以上見えている模様の検出率：細かい模様 73% → 93%、粗い模様 40% → 70%
- 実写写真で反応したビュー：横断歩道 35% → 61%、階段 36% → 64%、鍵盤 19% → 41%、フェンス 18% → 43%、金網 11% → 26%、キーボード 33% → 51%
- 手持ちで模様に向けてから鳴るまで：遅い側（90 パーセンタイル）1.5 秒 → 0.4 秒。見えている間に鳴っている割合 54% → 78%
- 模様のない場面（人物・自然・机など）で鳴り始めるループ：毎分 9 → 13.5。増えた分の多くは背景にある本物の繰り返し（チェックのシャツ、本棚、象嵌の縞など）
- 原因は主に 3 つだった：セルが重ならず模様がセルの格子とずれると拾えない／粗い模様（画面幅の 13% 超）を見る階層がない／「全エネルギーの 40% が 1 方向」という条件が、陰影や輪郭の多い実写では満たせない

**まだ確かめていない** — 企画書の「検証すること」に対応：
- [ ] 実機（iPhone / Android）での検出の安定性と処理速度。特に古い機種
- [ ] 会場照明・カメラのピンぼけ・手ぶれでのちらつき（`TRACKER_DEFAULTS` と感度で調整）
- [ ] ポスター以外（床・壁・服・街）に向けたときのうるささ（上限・感度・閾値）
- [ ] 強いぼけでは点の並びが GRID 寄りに判定される（`dotsCross`）。太い線の格子は DOTS 寄りになる
- [ ] 放射は縞の間隔が半径で変わるため検出が弱め。ポスター側で中心を空ける・本数を増やすと安定する（デモポスター fig.7 参照）
- [ ] 同心円は実写・合成とも検出が弱い（合成シーンで正しく同心円と判定できたのは 28 中 7）。リングの上に縞の領域が重ねて出ることがある
- [ ] 細い針金が背景の前にある金網のような模様は、まだ半分以上取りこぼす
- [ ] 複数領域の間隔比（3:4:5）を領域間のポリリズムとして鳴らす仕組み（現在は格子の内部比のみ）
- [ ] 実際のポスター構図での「どこから入ってどこへ抜けるか」の展開
